## Required implementation and validation

1. **Honest, usable machine contracts.** Audit every capability entry's advertised request and response schema IDs against the actual JSON schema definitions and TypeScript declarations. Add missing definitions, fix incorrect references, or remove claims for unsupported operations. Provide a repeatable test resolving every advertised schema reference and validating representative payloads. Ensure each published schema describes actual outputs (including trace, cell explanations, and errors), not merely superficial top-level fields. Document any transport-specific envelope differences.

2. **One authoritative, accurate diagnostic path.** Ensure `off`, `regular`, and `deep` do not change grants, validation decisions, revisions, files, mutations, or rollback outcomes. Regular mode must report the same authoritative coded decision as deep; successful deep transactions must include actual captured validation steps where the contract advertises traces, not a manufactured success-only trace. Capture denial and rollback at the decision site. `trace.truncated` must become true *only when a step was omitted*, not merely when 32 steps were captured. Validate the requested debug level and reject unknown values rather than silently downgrading. Apply record, trace, text, repairs, and nested-data budgets with truthful truncation indicators where needed; do not let untrusted operation IDs, region IDs, error strings, or facts cause unbounded payloads. Diagnostic generation must not leak unauthorized facts on permission-denied requests.

3. **Bounded, actor-scoped inspection on every path.** Audit `AgentWorldApi.inspect(actor)`, `ProgrammerWorldApi.inspectMap(actor,bounds)`, paginated region and operation inspection, `explainCell`, placement-surface inspection, preview, and CLI equivalents. Require appropriate grants for each surface and consistently enforce implementation-owned limits without enabling bypass through alternate/legacy endpoints. Fix the legacy all-regions response via bounded summary or pagination and document any compatibility impact. Preserve sparse write-mask semantics and the separation of authored base from projected facts. Inspect operations should not reveal private data beyond the actor's intended scope.

4. **Efficient single-cell and bounded-map reads.** Avoid a full 500x500 array clone/projection for `explainCell`: evaluate only the requested cell and the relevant overlapping regions, with identical semantic results. Where practical, make bounded `inspectMap` cost scale with requested cells and relevant regions rather than total world size. Include repeatable 500x500 benchmarks with representative region counts and request sizes; report elapsed times and allocations/heap deltas with environment and methodology. Do not claim Windows/4 GB validation unless run on that hardware. Keep test inputs small enough for CI and no per-cell large-world rebuild.

5. **Regression tests and documentation.** Test schemas against concrete outputs; missing/invalid actors and grants; malformed debug values; successful and failed regular/deep transactions; exactly-32 and over-32-step trace behavior; masked cells, locked and authored-base cells; stale revisions and rollback; bounded pagination/legacy reads; behavior equivalence across debug modes and cross-surface reads. Run `npm test`, `npm run build`, `node examples/world-api-diagnostics.mjs`, and 500x500 CLI smoke checks including inspect-map and explain-cell. Record exact commands, outcomes, benchmarks, and remaining limitations. Update `docs/WORLD_API_V1.md`, `docs/CODEX_HANDOFF.md`, and any affected schema/type files to reflect implementation rather than future intent.
