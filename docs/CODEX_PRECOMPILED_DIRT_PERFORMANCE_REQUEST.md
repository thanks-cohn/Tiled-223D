## Nonnegotiable visual specification

**First release is deliberately plain.** A mostly flat landmass displays three configurable brown tones in broad, believable regions (suggested medium/light/dark; preserve creator palette choices) with **no outlines, decorative black lines, contour bands, gradients, edge strokes, vegetation or additional mesh subdivisions merely to color dirt**. No `new THREE.Color()` or per-point procedural color noise in every normal gameplay frame. The overall map-aligned silhouette, separate coastline, original islands, and existing ocean remain intact. Distant brown terrain should be visually close to an ocean-cost material/mesh or map-aligned low-res overlay, not a dense continuously regenerated full-world surface.

Physically meaningful elevations and original ramps remain! Do **not** flatten actual ramp/landing geometry to achieve a fast but false visual. At the near interactive LOD, terrain vertices, collision/ground samples, ramp dimensions and normals must agree within documented tolerances. A compact precompiled height representation or low-cost local patch may be used where necessary. The far/orbital view may simplify noninteractive detail, but its geographical outline and color distribution must still correspond to the canonical landmass and **never paint over either original island**. If a visual LOD is too coarse to show a ramp, it must not advertise itself as near collision-ready geometry.

## Compile-once pipeline — one persistent dirt asset per effective expansion model

1. **Canonical source is the sole authority.** Read the saved original 500×500 Tiled-relative dirt footprint, physical feature/ramp IDs and geometry, seed, palette, constraints, authored patches and canonical source revision. Do not regenerate, reroll or independently sample landmass shapes/ramps for larger modes.
2. **Build a compact prepared/compiled artifact for each Current, Bigger and Massive effective expansion profile** from that same saved canonical source. Each record includes `worldId`, relevant scale coordinates, selected `inherit-world` or landmass `replace` policy, effective profile ID/version, canonical source hash/revision, compiler algorithm/schema version, geographic footprint/color asset reference, exact original fixed-feature physical geometry, and a monotone mapping/interval table. Gap *lengths* change, ramp sizes/IDs/shape/collision never do. Do **not** multiply a replacement profile by the inherited one. The compilation should be initiated explicitly in a build/editor/authorized API phase, not every few gameplay seconds.
3. **Practical persistence contract:** store compact manifests as JSON if convenient, a tiny three-tone texture/atlas or lookup table for visuals, and **bounded indexed elevation/ramp data as compact binary/typed arrays or a more efficient cached representation where numerical JSON would be costly**. JSON is preferred for readable metadata, schema/version, provenance and editable mathematical constraints, but it is not mandatory for huge vertex/height arrays. Do not save enormous full 2,500² or 16,000² dense grids, pre-generate millions of mesh vertices, ship thousands of tiny network requests, or keep all three worlds' full-resolution meshes in memory. “Precompiled” means expensive decisions/math and identities are resolved before gameplay, with inexpensive indexed lookups and cached **bounded** geometry available on approach; it does not mean every polygon of all three worlds must remain loaded.
4. **Persist/reuse the compiled results.** A file-backed asset under an appropriate existing project/build location should be versionable, discoverable by the browser and reproducible after restart. Include a manifest listing file paths, measured byte sizes, sample density/LOD, source/profile versions and checksums or equivalent coherence keys. Provide build scripts or a documented existing build hook to emit/rebuild Current/Bigger/Massive. On cold launch select and load the matching manifest; if compilation is unavailable/stale, expose a clear capability/error or perform an explicitly bounded preparation path, not an invisible multi-second frame-blocking rebuild. For browser distribution, consider bundled/static assets with fetch-on-demand and bounded caches; do not assume the browser can write to repository files.
5. **Creator overrides and invalidation:** on source revision changes, explicitly recompile affected modes/features. When *only the three brown colors* change, update the color material/asset without unnecessarily regenerating physical ramps or elevations. When only a Bigger-specific profile changes, invalidate only the affected Bigger compiled artifact. An ocean-like profile replacement on Current needs its own matching artifact/cache key and cannot silently reuse an incompatible Current default. For arbitrary creator profiles, compile on demand via an explicit editor/API operation with preview, progress and permission/revision checks; do not claim that only three hardcoded presets can ever be customized.

**Important 2D/route nuance:** the current interpreter is a one-main-route proof, not an arbitrary 2D invertible terrain warp. Keep its documented bounds honest. Canonical overview mapping and internal journey mapping must remain distinct. Compile the actual supported semantics and emit a clear unsupported/invalid-map diagnostic for ambiguities; do not silently approximate the canonical 2D geography by distorting ramp geometry or wrapping an experience coordinate into an unrelated cell. Expand only eligible space *between* protected features, and preserve the original landmass's normalized outline at each external world size.

## Cheap render and physical approach

- **Far/orbital:** use one or a very small number of reusable, static/map-aligned coarse surfaces whose coloring comes from an inexpensive precompiled three-tone asset/material. Prefer a simple ocean-like plane/patch with cheap shoreline masking; clip authored islands from that surface and prevent ocean/ground overdraw and Z-fighting. No 113×113 costly procedural resampling every scale switch; select a precompiled far representation when possible. At 16,000-world scale the renderer must not allocate a 16,000² height map.
- **Near-ground:** reserve detailed physical/visual geometry for a bounded neighborhood around the player and saved ramp/meaningful elevation footprints. Read precompiled heights/feature records with O(1) indexed lookups or a spatial index, avoiding a scan of all saved ramps for each vertex. Use persistent chunk addresses, precomputed/cached meshes, reusable geometry buffers, small LOD tile resolution, conservative safe ramps, and deterministic reconstruction. Choose a design that avoids the existing 9,409-vertex all-at-once main-thread rebuild after each ~32 units of movement. If on-demand construction remains, increment it within an explicit frame time budget or prefetch/worker it safely; terrain edits, camera changes and normal driving must never force a giant synchronous rebuild. GPU upload/render costs also need a bounded plan.
- **Collision:** use the same saved height/ramp data and the same experience-to-canonical coordinate transform as the close rendering and flight/ground collision. Broad-phase spatial indexing must avoid scanning an entire ramp list or re-noising an entire continent per sample. Prefetch collision-ready terrain before high-speed travel reaches it. Do not make an invisible or incorrect proxy collider merely to improve FPS.
- **Memory discipline:** treat the ~4 GB Windows device as a constraint. Keep at most a small bounded near-cache and the active selected world's compact files, avoid redundant copies of 250,000-cell arrays/large buffers in both viewer and API, and dispose outdated resources on scene/profile changes. Loading far visuals should not require near physical terrain for the entire world. Avoid extra shaders/effects for black lines and gradients in this phase.

## Expand API/Dirt: compiler, assets, live diagnostics and agent-first debugging

Reuse the existing versioned `dirt-v1` programmer + agent core, creator permissions, expected revisions and commit/undo; introduce a separately versioned `compiled-terrain-v1` capability if existing payloads cannot express these features safely. No unrelated full rewrite and no unguarded mutation through a debug global. Extend **`API/Dirt/`** with real tested call signatures, typed request/response schemas, source/provenance, and explicit CLI-vs-browser capability boundaries. Suggested operation families (refine names in code/docs together):

- `dirt.inspectCompilation`, `dirt.listCompiledProfiles`, `dirt.inspectCompiledAsset`: list canonical source/profile revisions, prepared Current/Bigger/Massive asset IDs, sizes, paths, versions, effective expansion, fixed ramps and gap counts, valid/stale state, loaded/evicted cache condition, compile cost and freshness.
- `dirt.planCompilation`, `dirt.previewCompilation`, `dirt.validateCompilation`, `dirt.compileProfile` or staged authorized `dirt.commitPlan`: choose world/profile, bounded color/physical LOD budgets, before/after asset sizes, known invalidations and expected revision; explicitly compile once with progress and cancellation or documented safe rollback. No unreviewed source/Tiled mutation; a build CLI can write derived assets to a clearly separated generated location.
- `dirt.inspectVisualAt` and `dirt.inspectPhysicalAt`: given exact `worldId`, coordinate space and bounded coordinates, show color index/source asset, canonical mask/height, ramp ID/collider, compiled-height lookup, active LOD, nearest protected feature, source/profile version, and why visual and physical heights differ (if they do).
- `dirt.inspectRuntimePerformance` plus `dirt.explainStutter`: extend the browser-only measured reporter to expose stage timings and cache hit/miss, geometry builds/uploads, material/texture work, prefetch readiness, frame gaps and selected coordinates, with bounded per-frame event history and honest CPU/GPU distinction. An agent must be able to compare a specific long-frame timestamp with the exact terrain operation that ran in it. Keep local snapshot export explicit, bounded and privacy-aware; **CLI cannot see a separate live browser** and must say so.
- `dirt.diffCompiledProfiles`, `dirt.validateCompiledTerrain`: compare same fixed ramp IDs/shapes/physical dimensions, canonical footprint, expanded gaps, actual render/collision height agreement, and source/profiles across all three modes or a replacement profile. Return machine-readable errors when cache keys are stale, unsupported 2D mapping, regions overlap protected islands, compiled manifest is missing, physical texture doesn't align or a GPU/upload budget is exceeded.

For any unfinished operation, report `NOT_IMPLEMENTED` with a truthfully scoped capability flag. Programmer/agent documentation must show which operations actually ship, how to invoke them via the Node/CLI and browser, and how to capture a before/after stutter report. Keep advanced world API and original-island protection untouched.
